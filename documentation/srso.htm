LinuxKI Warning

 

Speculative Return Stack Overflow (SRSO) mitigation may negatively impact performance

Date: 12/17/2025

Problem

In August of 2023, AMD documented a new speculative side channel attack vulnerability that impacted AMD EPYC 1st-4th Generation processors.   The security vulnerability, also known as Speculative Return Stack Overflow (SRSO) is documented in CVE-2023-20569 and in AMD Security Bulletin AMD-SB-7005.     AMD introduced a microcode/firmware to mitigate the attack, which was incorporated into HPE firmware in 2023.    Meanwhile, OS mitigations were also released to address some remaining vulnerabilities that are not covered in the microcode.  

The purpose of this article is to show how the OS mitigation, enabled by default, can negatively impact performance using a recent customer case study.  

Problem description

Customer was running MongoDB on a VMWare 23 vCPU VM running on a Dell PowerEdge R740xd using the 2x Intel® Xeon® Gold 6248R (2-sockets 3.0 GHz) processors using 4 direct-attached NVMe drives configured in a MD RAID10 volume.   When the VM was migrated to an HPE ProLiant DL385 Gen11 server using the 2x AMD EPYC 9554 (64-core, 3.1 GHz) with 4x direct-attached NVMe drives in a MD RAID10 volume, the DL385 server underperformed the older Dell server.

Suspecting a potential I/O issue, the customer use fio to benchmark the I/O performance.    To remove the virtualization layer from the equation and “prove” the performance was with the DL385 I/O, the customer an fio on the Dell VM and HPE VM as well a bare-metal DL385 and compared the results.   The following fio command was used in the results:

 

$ fio -direct=1 -iodepth=128 -rw=randrw -ioengine=libaio -bs=4k -size=50G -numjobs=4 -runtime=60 -group_reporting -filename=/datos/fio_test -name=randrw_test

 

The results of the test are as follows:

 

DELL VM (Intel)

HPE VM (AMD)

HPE BM (AMD)

530K

294K

340K

 

Investigation

Getting to the root cause

 

Understanding that CPU performance is more critical to the performance than the physical I/O was very important.   Note that the kparse output does show the following warning on both the Dell VM and HPE bare-metal environments:

 

Warning: Security mitigations present [INFO][Next]

 

Security mitigations are not that unusual and have been known to cause performance issues as noted by the article in the INFO link from the warning:

 

Side-Channel Attack (Spectrum/Meltdown) mitigation can negatively impact performance

 

Comparing the mitigations between the Dell (Intel) server and the HPE (AMD) server showed one mitigation specific to the AMD Gen1, Gen2, Gen3, and Gen4 processors (EPYC 9554 is a Gen4 processor):

 

/sys/devices/system/cpu/vulnerabilities/spec_rstack_overflow Mitigation: Safe RET

 

Solution

 

To resolve the issue, the SRSO mitigation was disabled by adding the following boot command line option:

 

spec_rstack_overflow=off

 

After adding this option to the HPE bare-metal server and the HPE VM, the results were in line with expectations:

 

DELL VM (Intel)

HPE VM (AMD)

HPE BM (AMD)

530K

478K

565K

 

Note the HPE VM results were slightly lower as the Dell VM with 23 vCPUs could easily fit on a single NUMA node (socket) on the DELL server while the HPE server with Memory Domains per Socket (NPS) set 4 would spread the VM across multiple NUMA nodes, potentially across sockets.   Plus, the Max CPU Frequency on the Intel server was also higher than the HPE server.   

 

While the OS mitigation can be disabled, it may leave the server open to the vulnerabilities that the OS code was designed to address.

 

5th Generation and later AMD EPYC processors are not impacted by the SRSO mitigation.

 

Summary

 

Be aware that the SRSO mitigation can impact performance. The impact could be minor or severe, and the problem could be disguised as something other than a CPU issue.      Note that LinuxKI will now display a Warning if the SRSO OS mitigation is present:

 

Warning: Speculative Return Stack Overflow (SRSO) mitigation detected and may impact performance [INFO][Next]
